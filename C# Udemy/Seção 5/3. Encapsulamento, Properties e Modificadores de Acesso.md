
<div><h1 align="center" style="color: #00ff00">Encapsulamento</h1></div>

Encapsulamento é considerado o primeiro pilar da orientação a objetos. Ele consiste em esconder detalhes de implementação de um componente, expondo apenas operações seguas e que o mantenha em um estado consistente.

-  O objeto deve sempre estar em um estado consistente, e a própria classe deve garantir isso.

> *1ª - Opção - Implementação Manual*

-  Todo atributo é definido como private (não vai ter acesso por outro arquivo)
-  Implementa-se métodos Get e Set para cada atributo, conforme regras de negócio
-  <span style="color:rgb(4, 255, 0)">Nota: não é usual na plataforma C#</span>

Vamos usar o projeto que tinhamos feito para produtos como exemplo.

```c#
private int _quantidade
```

Por convenção, na linguagem C# quando estamos trabalhando com atributos privativos, eles são escritos com underline seguido do nome todo em minúsculo.

Ok, mas da forma que está, como o atributo é privativo, não é possível acessar no método main. Para resolver isso, devemos criar métodos getters e setters.

> *Exemplo - Códigos Getters e Setters

```c#
public string GetNome(){
	return this._nome;
}
public void SetNome(string nome){
	_nome = nome;
}
```


<div><h1 align="center" style="color: #00ff00">Properties</h1></div>

As Properties vão melhorar o jeito que implementamos o encapsulamento. Não será preciso criar os métodos getters e setters para atributos.

Properties são definições de métodos encapsulados, porém expondo uma sintaxe similar à de atributos e não de métodos.

> *Exemplo - Definição de uma Property*

```c#
public string Nome {
	get {return _nome; }
	set{    
		if (value != null && value.Length > 1){
			_nome = value;
		}
	}
}
```

Nesse caso definimos um método com o nome do atributo e dentro dele nós criamos o get e o set. 

No set, o value é basicamente o valor do argumento que passamos como parâmetro, ele é uma palavara reservada.

##### Auto Properties

Auto properties é uma forma simplificada de se declarar propriedades que não necessitam lógicas particulares para as operações get e set.

> *Exemplo - Um produto que só pode exibir o preço, mas NÃO pode ser alterado*

Para resolver isso, seria necessário o atributo possui somente um getter o setter deverá ser private.

```c#
public double Preco { get; private set; }
public int Quantidade { get; private set; }
```

##### Ordem sugerida para implementação de membros

-  Atributos privados
-  Propriedades autoimplementadas
-  Construtores
-  Propriedades customizadas
-  Outros métodos da classe

Lembrando que assembly é um projeto que está em uma solução.

Os modificadores podem ser aplicados à classes

-  Acesso por qualquer classe
	-   public class Product
-  Acesso somente dentro do Assembly (Projeto)
	-  internal class Product
-  Acesso somente pela classe-mãe
	-  private class Product
	-  Nota: classe aninhada, por padrão é private
