<div><h1 align="center" style="color: #00ff00">Herança</h1></div>
-  É um tipo de associação que permite que uma classe herde dados e comportamentos de outra
-  Definições importantes
-  Vantagens
	-  Reuso
	-  Polimorfismo
-  Sintaxe
	-  : (estende)
	-  base (referência para a superclasse)

O base funciona como se fosse um "super" que vemos em OO com Python.

> *~={green}Exemplo=~*

```c#
namespace Heranca.Entities  
{  
    class BusinessAccount : Account  
    {  
        public double LoanLimit { get; set; }  
        public BusinessAccount(){}  
  
        public BusinessAccount(int number, string holder, double balance,  double loanLimit) : base(number, holder, balance)  
        {  
             LoanLimit = loanLimit; 
        }  
    }  
}
```

E dentro da subclasse eu só acrescento o atributo especializado, nesse caso, o loanlimit.

<div><h3 style="color: #00ff00">Upcasting e Downcasting</h3></div>

-  Upcasting

É o casting de uma subclasse para uma superclasse. Significa basicamente que estamos convertendo um objeto especializado em um objeto mais genérico. 

Um uso muito comum do upcasting é no polimorfismo.

> *~={green}Exemplo=~* 

*Converter um BusinessAccount para um Account*

-  Downcasting 

É o contrário, consiste em ser o casting da superclasse para uma subclasse. 

> *~={green}Exemplo=~*

*Converter um Account para um BusinessAccount*

No Downcasting nós temos palavras chaves auxiliares que vao ajudar ``as`` e ``is``. O downcasting é muito usado em métodos que recebem parâmetros genéricos (ex: Equals).

> *~={green}Exemplo - Upcasting=~*

```C#
Account acc = new  Account(1001, "Alex", 0.0);  
BusinessAccount bacc = new BusinessAccount(1002, "Maria", 0.0, 500.0);  
  
// UPCASTING  
Account acc1 = bacc;  
Account acc2 = new BusinessAccount(1003, "John", 0.0, 200.0);
```

Isso funciona porque o tipo de relação entre BusinessAccount e Account é "É um", ou seja, toda BusinessAccount também é uma Account.

Quando a atribuição ocorre no upcasting, somente os elementos pertencentes a subclasse são definidos, o que é da classe especializada é perdido.

> *~={green}Exemplo - Downcasting=~*

Entretanto, é mais complicado quando queremos fazer o caminho reverso, ou seja, converter de uma superclasse para uma subclasse.

```c#
// DOWNCASTING  
Account acc3 = new SavingsAccount(1004, "Anna", 0.0, 300.0);  
BusinessAccount acc4 = (BusinessAccount)acc3;
```

O Downcasting é uma operação insegura e deve ser testada para verificar se a variável é realmente do tipo desejado.

Para fazer o teste em uma instância e descobrir se ele é de um tipo ou de outro podemos usar o operador ``is``

```c#
if (acc3 is BusinessAccount){
	BusinessAccount acc5 = (BusinessAccount)acc3;
}
```

Outra forma de fazer o casting é usando o operador as

```c#
if (acc3 is BusinessAccount){
	BusinessAccount acc5 = acc3 as BusinessAccount;
}
```


<div><h3 style="color: #00ff00">Sobreposição</h3></div>

-  É a implementação de um método de uma superclasse na subclasse
-  Para que um método comum (não abstrato) possa ser sobreposto, deve ser incluído nele o prefixo "virtual"
-  Ao sobrescrever um método, devemos incluir nele o prefixo "override"

Basicamente, nós vamos usar as duas palavras, virtual e override, em combinação. A primeira dizendo qual método poderá ser sobrescrito e a segunda para dizer exatamente na subclasse que o método está sobrescrito.

-  Na superclasse Account, nós usamos o virtual

```c#
public virtual void Withdraw(double amount){
	Balance -= amount + 5.0;
}
```

-  Na subclasse SavingsAccount temos o código abaixo

```c#
public override void Withdraw(double amount){
	Balance -= amount;
}
```

Além disso, podemos ainda chamar a operação ou método da superclasse mesmo que estejamos em um método override, ou seja, que possa ser sobrescrito. Para isso, utilizamos a palavra reservada ``base``

> *~={green}Exemplo=~*

Suponha que a regra para o saque para conta poupança seja realizar o saque normalmente (superclasse) e depois descontar mais 2.0.

```c#
public override void Withdraw(double amount){
	base.Withdraw(amount);
	Balance -= 2.0;
}
```

Nesse caso, é possível reaproveitar a implementação da superclasse e adicionar somente o que é necessário na especialização.

<div><h3 style="color: #00ff00">Classes e Métodos Selados</h3></div>

Classes e métodos selados utilizando a palavra reservada ``selead``

-  Classes selados não podem ser herdadas. Entretanto, é possível estender a funcionalidade de uma classe selada usando "extension methods"

```c#
namespace Course {
	selead class SavingsAccount {}
}
```

-  Métodos selados evitam que um método sobreposto possa ser sobreposto novamente. Sendo assim, só podem ser aplicados para métodos sobrepostos.

```c#
public sealed override void Withdraw(double amount){
	base.Withdraw(amount);
	Balance -= 2.0;
}
```

Basicamente nesse método estou informando ao compilador que o método não pode ser sobrescrito novamente.
